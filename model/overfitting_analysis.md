이 문서는 **985 이탈 예측 모델**의 오버피팅 진단 결과와 훈련/검증 성능 차이가 발생한 원인을 분석한 보고서입니다.

## 📊 1. 진단 요약

모델은 전체 데이터의 80%로 학습되었으며, 나머지 20%의 데이터를 통해 검증되었습니다.

| 지표 (Metric) | 훈련 세트 (Train) | 검증 세트 (Valid) | **차이 (Gap)** |
| :--- | :---: | :---: | :---: |
| **ROC AUC** | 0.8857 | 0.8408 | **0.0449 (경미한 과적합)** |

> [!IMPORTANT]
> **진단 결과**: 일반적으로 AUC 차이가 **0.05 이상**일 때 "심각한 오버피팅"으로 간주합니다. 현재 985 모델은 **0.045** 수준으로, **경미한(허용 가능한) 수준**의 오버피팅으로 분류됩니다. 이는 모델이 훈련 데이터의 특정 패턴을 조금씩 암기하기 시작했음을 의미합니다.

## 🧐 2. 왜 오버피팅이 발생했는가? (원인 분석)

피처 중요도와 모델 구조를 바탕으로 분석한 성능 차이의 주요 원인은 다음과 같습니다.

### 1️⃣ 피처의 복잡성 (시계열 트렌드)
985 모델은 매우 정밀한 시계열 피처를 사용합니다:
- **`max_inactive_streak`**: 최근 30일간 앱 접속이 없었던 최대 연속 기간.
- **`engagement_slope`**: 사용자의 이용량이 증가하거나 감소하는 추세.
이러한 피처들은 예측력이 매우 강력하지만, 학습 데이터(2017년 3월)의 특정 상황에만 유효한 패턴일 가능성이 큽니다. 모델이 "이 특정 추세를 보인 사용자는 무조건 이탈한다"는 식의 규칙을 암기했을 수 있습니다.

### 2️⃣ 카테고리 기수성 (City, Registered Via)
도시(City) 코드나 등록 경로(Registered Via) 중 사용자 수가 매우 적은 항목들이 있습니다. 모델은 이러한 희소한 카테고리 내에서 일반적이지 않은 "노이즈" 패턴을 학습하여, 새로운 데이터에 적용할 때 오차가 발생할 수 있습니다.

### 3️⃣ 모델 깊이와 데이터 크기의 불균형
현재 **최대 깊이(Max Depth) 6**을 사용하고 있습니다. 약 25,000명의 데이터 세트에서 깊이 6은 모델이 최대 64개의 복잡한 규칙을 만들 수 있게 하며, 이는 훈련 데이터 내의 아주 작은 사용자 그룹까지 개별적으로 학습하게 만들 수 있습니다.

## 🛠️ 3. 개선 및 완화 방안

성능 차이를 줄이고 모델의 일반화 성능(강건성)을 높이기 위해 다음과 같은 전략을 제안합니다.

### ✅ 정규화(Regularization) 적용
`985ml.py` 스크립트에서 다음 파라미터를 조정할 수 있습니다:
- `reg_lambda`: L2 정규화를 강화하여 모델의 복잡도를 낮춥니다.
- `min_child_weight`: 리프 노드가 가져야 할 최소 샘플 수를 늘려, 소수 그룹에 대한 암기를 방지합니다.

### ✅ 트리 깊이 축소
`max_depth`를 6에서 **4**로 낮추면, 모델이 아주 세세한 규칙보다는 더 넓고 일반적인 패턴에 집중하게 됩니다.

### ✅ 희소 카테고리 처리
샘플 수가 적은 도시 코드를 "기타(Other)"로 묶어 모델이 불필요한 노이즈를 학습하지 않도록 방지합니다.
